# Nokia Experience: готовность к первому рабочему прототипу

**Решение:** исследовательский этап достаточен для начала нативного Android Launcher без ожидания растеризации MIF/AIF. Неподтверждённые элементы остаются заменяемыми asset/layout slots; их текущие значения нельзя называть точной копией N95. Целевая проверка — реальный Samsung Galaxy A5 (2017), Android 8 / API 26, физический экран 1920×1080. Android-проект и APK этим документом **не создаются**.

## 1. Что подтверждено

| Область | Доказанная основа | Можно использовать сейчас |
|---|---|
| N95 reference | `RM-320` Z-диск, `SYM.rom`, `system/data/Wsini.ini`: портрет **240×320**, landscape **320×240**; структура и системные компоненты в [N95_ANALYSIS.md](N95_ANALYSIS.md) | 240×320 — **только внутренняя координатная система N95**, не разрешение Android-интерфейса. Масштаб по X/Y одинаковый, с учётом фактической доступной области экрана. |
| Меню/папки | `private/101F4CD2/Content/appshelldata.xml` задаёт иерархию/UID, семь папок привязаны к ID `Menu.mif`; см. [DECODED_ASSETS.md](DECODED_ASSETS.md) | Фабричное дерево N95 как модель сцен, с Android-заменами действий и проверкой доступности. |
| Растровые MBM | 341 image ID успешно извлечены; размер, битность и источник перечислены в [MBM_IMAGE_INDEX.csv](ASSET_PREVIEW/MBM_IMAGE_INDEX.csv) | Размер и силуэт изображения известны; **103 индексированных Color256-превью не дают достоверной финальной палитры**, а 117 mask-пар пока гипотетичны. |
| Ручной набор | 51 файл `drawable-nodpi` исследован отдельно, 42 уникальных мотива; точное совпадение с исходным MIF не подтверждено; см. [MANUAL_ASSETS_CATALOG.md](MANUAL_ASSETS_CATALOG.md) | Временные app-icon placeholders с отметкой происхождения, без заявления об оригинальности. |
| Сенсорный UX | Дополнительный 5530 S60 5th Edition исследован отдельно в [S60_TOUCH_REFERENCE.md](S60_TOUCH_REFERENCE.md) | Идеи direct touch/scroll/selection/контекстных команд; **не** переносить его визуальные ресурсы и `360×640`-геометрию. |

## 2. Ресурсы, готовые к интеграции

- `Startup.mbm`: **20** проверенных кадров 240×320 RGB888, без встроенной прозрачности. Использовать только как **опциональную** короткую заставку внутри Launcher; тайминг оригинала не установлен. [Превью](ASSET_PREVIEW/Startup_contact_sheet.jpg).
- `enhancedsoftkeysbitmaps.mbm`: **24** серых/монохромных элемента 120×27, 120×21 и фрагменты. Их можно брать как изученный набор форм, но схему сборки и экранный цвет нужно оставлять изменяемыми. [Превью](ASSET_PREVIEW/enhancedsoftkeysbitmaps_contact_sheet.jpg).
- `avkon2.mbm`: **233** элемента generic UI, в том числе резервные силуэты приложений/папок, некоторые полосы и кандидаты на навигационные детали. Не назначать отдельному glyph значение батареи/WLAN только по сходству. [Превью](ASSET_PREVIEW/avkon2_contact_sheet.jpg).
- `callstatus.mbm`: **8** элементов/масок 25×23; пригодны как исследованный источник формы, но конкретные состояния вызова и цвета ещё не подтверждены. [Превью](ASSET_PREVIEW/callstatus_contact_sheet.jpg).
- NSeries/Series60 skin MBM: фактически декодированные фоны и полосы; поскольку фон для Launcher свой, преимущественно кандидаты для панели/края/выделения. Их назначение и активность темы пока неизвестны; не «запекать» их в неверную область.
- Ручные PNG — для app icons там, где исходные `_aif.mif` недоступны визуально. Рекомендуется явно вести `source=manual`, `confidence=provisional`, чтобы впоследствии заменить оригинальным рендером.

До интеграции оригинального контента проверить право на распространение иконок/звуков/анимации. Техническая доступность не равна разрешению на публикацию APK с этими ресурсами.

## 3. Что визуально недоступно

В N95 dump найдено **333 MIF**, из них **93 `_aif.mif`**. Их контейнеры/слоты инвентаризированы, но фактически визуализировано **0** оригинальных MIF/AIF-иконок; на выходе пока нет проверенных PNG для Phone, Contacts, Messaging, Camera, Calendar, Clock, Browser, Gallery, File Manager, Music и папок `Menu.mif`. Векторные `Menu.mif`, `avkon2.mif`, `callstatus.mif`, `_aif.mif` и skin MIF требуют проверенного Symbian MIF/SVG-T(SVGB) рендерера либо S60 `AknIconUtils`/EKA2L1. Файлы `.skn` и `.rsc` тоже не декодированы до полного набора цветов и layout-параметров. [Подробный реестр слотов](ASSET_PREVIEW/MIF_SLOT_INDEX.csv).

Не блокировать разработку: у каждой логической иконки/графики панели должен быть стабильный **semantic asset slot** (`app.phone`, `folder.tools`, `status.battery`, `selection.menu`, `softkey.left`, …), за которым сначала стоит проверенный MBM или помеченный placeholder, а позднее — оригинальный MIF-render. Нельзя объявлять ручной значок «доказанной иконкой N95» по имени файла.

## 4. Что придётся воссоздать поведением и геометрией Android

- Home/Active Standby, Nokia status pane, Main Menu, папки, selection/highlight, softkey-подписи и scrollbar — как собственные представления/сцены Android, не Symbian-бинарники.
- Контекстные команды softkeys и стек Back. Softkeys визуально N95, **сенсорные** с расширенными невидимыми hit areas; виртуальных N95 D-pad/клавиш нет.
- Touch: tap → открыть/выбрать, long press → контекстное меню, вертикальный drag/swipe → прокрутка, горизонтальный свайп лишь в обоснованной сцене, drag & drop только если предусмотрено моделью, мгновенный pressed feedback. Исторический double-tap 5530 не навязывать.
- Размещение на Android: фактические `WindowInsets`, системные/navigation areas, плотность и ориентация; legacy-графика масштабируется **одним коэффициентом** из canonical N95 reference, touch-области задаются по физически удобным `dp`, текст — `sp`. Экран 1920×1080 не гарантирует такую же доступную Launcher-область.
- Состояния батареи, сети, WLAN, Bluetooth, профиля и уведомлений: данные Android через адаптеры с явным «недоступно»/отсутствует при ограничениях разрешений. Собственная Nokia status pane не заменяет глобальную Android status bar в сторонних приложениях.

**Не выдавать за измеренные значения:** высоту/границы N95 status и softkey pane, сетку ячеек, icon render box, text baseline, selection rect, scrollbar и точные цвета активной темы. [Текущий статус измерений](N95_GEOMETRY.md), [палитра](N95_COLOR_PALETTE.md). До получения экранных эталонов это конфигурируемые layout/theme tokens, а не «восстановленные пиксели».

## 5. Желательные данные от N95/EKA2L1, не блокирующие прототип

1. Не масштабированные кадры RM-320 240×320: Home, Main Menu, каждая папка, выбранный элемент, Options, список с прокруткой, status/softkey в разных состояниях; фиксировать активную тему, язык, ориентацию и версию прошивки.
2. Pixel measurement границ панелей/ячеек/подписей/выделения/скролла и последовательностей анимаций; привязка кадров к конкретным MBM/MIF image ID.
3. Состояние C-диска/выбор активного skin и декодирование `.skn` для цветов. Исходный Z-диск содержит несколько skin, но не гарантирует, какой выбран пользователем.
4. Если появится проверенный MIF/AIF renderer — экспорт с фиксированным provenance и повторная визуальная проверка; без нового инструмента инвентаризацию не повторять.
5. Отдельно для 5530 — наблюдение реальных touch transitions/hitboxes, только как уточнение UX, не как замена N95 макета.

## 6. Архитектура первого прототипа

Нативное приложение Kotlin + Android Views/custom Canvas, `minSdk` не выше **26** для обязательной конфигурации (точное значение проекта определять при старте реализации). Ни Symbian OS, ни ROM внутри APK. Один Home Activity (`MAIN`/`HOME`/`DEFAULT`), сцены `Home`, `Menu`, `Folder`, overlay контекстных команд; однонаправленное состояние экрана и стек навигации. Отдельные модули/классы ответственности:

| Слой | Ответственность |
|---|---|
| `S60CanvasMapper` | N95 reference 240×320 / 320×240 → доступная Android область с единым scale, безопасные поля и orientation rules |
| `NokiaSceneRenderer` | Home, status pane, меню/папки, selection, softkeys; цвета/размеры только через заменяемые tokens |
| `TouchNavigationController` | tap, long press, scroll, optional swipe, Back; доступность всех команд без аппаратных N95 клавиш |
| `AssetRepository` | semantic slots → ресурс, source ID, маска/alpha, placeholder policy, кэш битмапов нужного размера |
| `MenuModel` | N95 дерево + пользовательские перестановки, состояние папок и доступность Android-приложений |
| `AndroidActionResolver` | `PackageManager.resolveActivity`/`queryIntentActivities` и безопасный запуск `Intent`; отсутствие приложения не вызывает падение |
| `DeviceStateAdapters` | батарея, сеть, Bluetooth, аудио, уведомления; разрешения/доступ проверяются и graceful fallback |

Нужные API 26-совместимые механизмы: Home intent filter; `PackageManager`/`Intent` для Phone (`ACTION_DIAL`), Contacts, SMS, Camera, Gallery, Browser и сторонних приложений; `WindowInsets`/`DisplayMetrics`; `ACTION_BATTERY_CHANGED`/`BatteryManager`; `ConnectivityManager`; `TelephonyManager` по доступному разрешению; `BluetoothAdapter`; `AudioManager`; опциональный `NotificationListenerService` после явного включения пользователем; `SharedPreferences` для первоначальной конфигурации. Не закреплять Samsung package names. Новые Android API допускаются лишь за version guard с API-26 fallback.

## 7. Минимальный рабочий объём и этапы

| Этап | Результат | Критерий выхода |
|---|---|---|
| 1. Каркас Home | выбираемый Home Launcher, собственный фон, масштабируемый N95 canvas, корректные system bars/insets, обработка поворота | cold start и возврат на Home на Samsung A5 / Android 8 |
| 2. Nokia Home и status | Active Standby-зоны, время/батарея/сеть при доступности, собственный wallpaper, временные slots | нет ложных статусов и падений без разрешений/системных сервисов |
| 3. Меню и папки | S60-style grid, N95-иерархия, selection, scrollbar, touch softkeys/Back | открыть/закрыть меню и папки, tap/long press/scroll работают без виртуального D-pad |
| 4. Android actions | проверяемые intents Phone/Contacts/SMS/Camera/Gallery/Browser и список установленных приложений | действие запускает доступный обработчик; при его отсутствии понятный fallback |
| 5. Ресурсы/полировка | интеграция верифицированных MBM, временных manual icons, заменяемые MIF slots, опциональная Startup | provenance сохранён; N95-визуал не объявлен точным там, где не измерен |
| 6. Compatibility pass | реальный A5: Home/cold start/возврат, меню/папки, touch/Back, navigation areas, поворот, сторонние приложения, нет разрешений/приложений, память, silent mode, notification access, battery/network | стабильная работа на обязательной конфигурации; найденные отклонения задокументированы и исправлены |

**Следующее действие после подтверждения пользователя:** начать только этап 1, затем последовательно проходить критерии выхода. Этот документ фиксирует готовность и план, а не реализует приложение.
