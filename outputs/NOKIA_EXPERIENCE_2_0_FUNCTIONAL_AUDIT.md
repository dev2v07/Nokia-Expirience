# Nokia Experience 2.0 — функциональный аудит

Дата: 2026-11-11
Ветка: `samsung-ux-architecture`
Контрольная точка: `nokia-exp-working-before-exp2`

## Метод и ограничения

Проверены исходники `LauncherActivity`, `HomeWorkspaceModel`, `MenuModel`, `MenuOrganizer`, `WidgetPreviewPicker` и `VisualProfile`, а также ключи SharedPreferences и JSON-контракты. Выполнен статический аудит путей Drop/commit/cancel. Автоматические Android UI-тесты в проекте не обнаружены; Gradle wrapper отсутствует, поэтому сборка и живой UI-сеанс этим аудитом не подтверждены. Samsung-материалы использованы как сравнительный UX-источник, а не как исходный код.

## Результаты

### Home Screen

| Сценарий | Статический результат |
|---|---|
| Перемещение внутри страницы | Реализовано через `trackWorkspaceDrag`, `previewReorder`, `HomeWorkspaceModel.reorder`. Соседи сдвигаются, а не просто меняются местами. |
| Между страницами | Реализовано; edge-hover переключает существующие страницы. |
| Drop на иконку | Реализован hit-zone и финальный commit только в `ACTION_DROP`; папка создаётся только на Drop. |
| Отмена/Drop вне области | Для Exp 2 после отмены состояние preview очищается; после edge-crossing исходная страница восстанавливается. |
| Новая страница | Есть временная пустая страница с `+`, она не записывается в `home_workspace`; создание происходит только при явном Drop на неё. |
| Сохранение | JSON-ключ `home_workspace` сохраняется через `HomeWorkspaceModel.save()`. |

Вывод: базовые требования Home покрыты. Сетку 4×3 и формат JSON менять не нужно.

### App Drawer

| Сценарий | Статический результат |
|---|---|
| Перемещение и reorder | Реализованы `drawerIndexAt`, `previewDrawerReorder`, `MenuOrganizer.moveToIndex`. |
| Папка на Drop | Создание папки происходит только в `applyDrawerDrop`, вызываемом из `ACTION_DROP`, при попадании в область иконки. |
| Папка → приложение | Для обычных установленных приложений поддерживается; добавление в существующую папку поддерживается для `installed:*`. |
| Переименование/удаление | Есть через контекстное меню, хранение в `menu_state`. |
| Скрытые приложения и порядок | Хранятся в `MenuOrganizer` и не сбрасываются при перерисовке. |
| Отмена после edge-hover | Найдена проблема P1: `endDrawerDrag()` при `!event.getResult()` и `drawerCrossedEdge` вызывает `moveToIndex`. То есть отмена после перехода страницы может изменить порядок без подтверждённого Drop. |

Вывод: единственное подтверждённое функциональное несоответствие — commit отменённого edge-drag в Drawer. Исправление должно быть локальным: отменённый Drag очищает preview и всегда восстанавливает порядок; reorder выполняется только в `ACTION_DROP`.

### Widgets

- Используются штатные `AppWidgetHost`, `AppWidgetManager`, `AppWidgetHostView`, `AppWidgetProviderInfo`.
- Добавление проходит через picker/bind/configure и выделяет widget ID.
- Long press открывает handles; в Exp 2 запускается перемещение.
- Перемещение между страницами хранится в `widget_page_<id>`.
- Resize учитывает provider resize mode и сохраняет `widget_width_<id>` / `widget_height_<id>`.
- Удаление требует подтверждения, удаляет запись из `widgets` и удаляет Android widget ID только если он не используется вторым профилем.
- Восстановление выполняется из `widgets` через `restoreWidgets()`.

Вывод: AppWidgetHost заменять нельзя и технической причины для замены не найдено. Нужны только ручные UI-проверки на реальном устройстве/эмуляторе: bind, configure, resize и восстановление после process restart.

### Профили и данные

- `nokia_experience` используется для N95/5530.
- `nokia_exp_2` используется для Nokia Exp 2.
- `loadProfileData()` заново создаёт `MenuModel`, `HomeWorkspaceModel` и `IconStore` при переключении профиля.
- `home_workspace`, `menu_state`, `widgets`, `widget_page_*`, `widget_width_*`, `widget_height_*` читаются из активного профиля.
- Exp 2 получает одноразовую начальную копию старого состояния через `initialized` и `profile_settings_initialized`; дальнейшей синхронизации нет, что сохраняет независимость профилей.
- При переключении профиля вызываются `restoreWidgets`, `buildDock`, `refreshGrid`, `refreshWorkspace`.

Вывод: разделение профилей сохранено. Требуется живой тест с разными иконками, папками и виджетами в каждом профиле; исходники не дают основания менять хранилище.

## Сопоставление с Samsung Experience 9.0

Внедрять следует только эти проверяемые UX-принципы:

1. Drag-сессия имеет стадии preview/commit/cancel.
2. Папка создаётся только после Drop непосредственно на иконку.
3. Reorder между иконками не создаёт папку.
4. Edge-hover переключает страницу, но не коммитит состояние сам по себе.
5. Widget editing остаётся на Android AppWidget framework.

Samsung Launcher остаётся отдельным privileged APK со своими provider/permissions/storage. Его APK, закрытый код, JSON/DB и permission-модель в Nokia не переносятся.

## План внедрения

### P1 — обязательно

Исправить только `endDrawerDrag`: отмена или Drop вне допустимой области не должна вызывать `MenuOrganizer.moveToIndex`. Сохранить существующий порядок и `menu_state`.

### P2 — после ручной проверки

Добавить небольшие тестируемые pure-методы или диагностический слой для определения `commit/cancel`, если это позволит покрыть сценарии без Android UI. Не менять модели хранения и не выносить весь `LauncherActivity`.

### Не требуется

Замена `AppWidgetHost`, миграция SharedPreferences/JSON, изменение сетки, новый Samsung storage, копирование APK, переписывание `LauncherActivity` и массовый рефакторинг.

## Решение

До исправления P1 код функционально близок к требуемой модели Samsung UX, но App Drawer не полностью соблюдает правило отменяемого Drag. Следующий безопасный кодовый шаг — один локальный fix P1 и затем ручная проверка всех перечисленных сценариев в трёх профилях. До этого пользовательские данные не затрагиваются.

## Продолжение аудита

### Дополнительные проверки папок Drawer

- `MenuOrganizer` сохраняет папки, назначения, скрытые приложения и порядок в одном JSON `menu_state` активного профиля.
- Удаление папки не удаляет приложения: assignment очищается, поэтому приложения возвращаются в общий список.
- Перемещение приложения из папки обратно в общий список предусмотрено через действие «Переместить в папку» → «Все приложения».
- Прямой Drop элемента из открытой папки наружу отдельно не реализован и должен быть проверен как UX-решение. Это не следует добавлять автоматически, пока не согласовано: текущая модель уже имеет безопасный обратный путь через контекстное меню.
- Порядок элементов папки и общий порядок используют один `order`; нужна ручная проверка, что вход/выход из папки не меняет порядок соседних элементов.

### Дополнительные проверки виджетов

- `onResume()` запускает `widgetHost.startListening()`, `onPause()` останавливает его; это соответствует жизненному циклу Android AppWidgetHost.
- При восстановлении отсутствующий `AppWidgetProviderInfo` тихо пропускается. Это безопасно для запуска, но требует ручной проверки после удаления или обновления provider-пакета.
- Отмена picker/bind/configure освобождает выделенный widget ID.
- При переключении профилей один Android widget ID может присутствовать в обоих профилях после одноразового копирования Exp 2. Код удаляет ID только если он больше не используется вторым профилем; это нужно проверить на устройстве.
- Автоматическое восстановление после process restart пока не подтверждено живым тестом: статически путь `widgets` → `restoreWidgets()` существует.

### Дополнительные проверки профилей

- N95 и 5530 используют `nokia_experience`; Exp 2 использует `nokia_exp_2`.
- `IconStore` получает активное хранилище профиля, а Exp 2 дополнительно использует bundled mapping из `assets/exp2_custom/mapping.json`.
- Переключение профиля пересоздаёт модели и вызывает `restoreWidgets`, `buildDock`, `refreshGrid`, `refreshWorkspace`.
- Одноразовый seed Exp 2 не должен повторно копировать или перезаписывать изменения пользователя; это следует проверить последовательностью: изменить legacy → один раз открыть Exp 2 → изменить оба профиля → повторно переключить.

### Что ещё не доказано без UI-сеанса

Не подтверждены автоматически: точная геометрия hit-zone на реальном экране, отмена Drag системным жестом, edge-hover пальцем, bind/configure стороннего виджета, сохранение после убийства процесса и независимость всех трёх профилей после серии переключений. Эти проверки нельзя заменить чтением Samsung APK или статическим анализом.
