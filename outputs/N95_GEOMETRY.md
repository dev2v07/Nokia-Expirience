# Эталонная геометрия Nokia N95 8GB и границы подтверждения

Здесь записаны только размеры, которые прочитаны из RM-320 и реально декодированных изображений. `240×320` — координатный холст оригинального N95 в портретном режиме, **не** целевое разрешение Android-интерфейса. Samsung Galaxy A5 (2017), Android 8 / API 26, экран 1920×1080 является обязательной будущей целевой конфигурацией, но её доступный размер для Launcher определяется во время работы с учётом системных областей.

## Подтверждённая система координат

`Z:/system/data/Wsini.ini` явно задаёт режимы экрана:

| Режим RM-320 | Ширина×высота исходного окна | Поворот | Дополнительная запись |
|---|---:|---:|---|
| `SCR_WIDTH1/HEIGHT1` | 240×320 | 270° | `S60_SCR_STYLE_NAME1 QVGA2` |
| `SCR_WIDTH2/HEIGHT2` | 320×240 | 0° | `S60_SCR_SOFTKEY_LOCATION2 right` |
| `SCR_WIDTH3/HEIGHT3` | 320×240 | 180° | `S60_SCR_SOFTKEY_LOCATION3 left` |

`Wsini.ini` подтверждает внешний экранный режим; он не содержит прямоугольников status pane, main pane или control pane. Бинарные `AknLayout2.dll`, `AknLayout2adaptation.dll`, `AknLayout2scalable.dll`, `menu2.r01` и `Avkon.r01` присутствуют, но их layout-константы на этом этапе не декодированы.

## Размеры визуальных ресурсов, не размеры панелей

| Элемент из исходного ресурса | Фактические размеры в пикселях N95 | Что можно и нельзя заключить |
|---|---|---|
| `Startup.mbm` ID 0–19 | 240×320 | полноэкранные кадры; не задают размеры рабочих панелей |
| `enhancedsoftkeysbitmaps.mbm` ID 0/1/4/6/13/16 | 120×27 | широкие фоновые сегменты и маски softkeys; 27 px — высота конкретной картинки, не доказанная высота всей softkey pane |
| Там же ID 2/3/5/7 | 120×21 | второй набор длинных softkey-сегментов/масок; возможно другое состояние или разбиение |
| Там же ID 8/9/10/11 | 104×21 | укороченные сегменты; точная позиция неизвестна |
| Там же ID 12/14/15/17/18/19/20/21/22/23 | 4×21, 8×21, 40×21 | края и короткие фрагменты, нуждающиеся в правилах сборки |
| `avkon2.mbm` ID 0–27 | 107×16 | полосы/вкладки базового UI; положение на экране неизвестно |
| `avkon2.mbm` ID 73–136 и 159–170 | 30×40 | generic app/folder silhouettes; не подтверждает размер ячейки сетки |
| `avkon2.mbm` ID 137–158 | 113–120×8–10 | горизонтальные полосы, кандидаты для выделения/рамок; реальный selection rect неизвестен |
| `avkon2.mbm` ID 205–232 | 12×15 | элементы, визуально похожие на стрелки/края скролла; геометрия scrollbar не подтверждена |
| `callstatus.mbm` ID 0–7 | 25×23 | пиктограммы состояния вызова; высота status pane из них не следует |
| NSeries skin MBM | отдельные 240×30, 240×27, 240×3, 215×30/7, 145×18 | растровые полосы/фрагменты темы; без `.skn` нельзя однозначно назначить pane и insets |

Файлы `.mif` содержат масштабируемые записи; исходного фиксированного icon size для `Menu.mif`, `_aif.mif` и `avkon2.mif` текущий контейнерный анализ не дал. Семь icon ID папок подтверждены `appshelldata.xml`, но размеры их отрисовки пока неизвестны.

Ручной набор [drawable-nodpi](MANUAL_ASSETS_CATALOG.md) имеет размеры иконок 144–306 px и составных частей часов 512×512 px. Это размеры скачанных Android-файлов, **не** измеренная геометрия N95; использовать их для вычисления menu cell или pane нельзя.

## Геометрия экранов: состояние измерения

| Что нужно будущему UI | Текущая доказательная база | Статус |
|---|---|---|
| Status pane: границы, высота, иконки батареи/сети | `Wsini.ini`, `avkon2.mif/.mbm`, skin strips | **не измерено**; наличие 240×30 в skin не доказывает 30-px pane |
| Softkey pane: границы, высота, зоны подписей | MBM с 120×27/21 и фрагментами | графика известна, **pane и text baseline не измерены** |
| Main menu: число колонок/строк, cell rect, поля | `menu2.r01`, `AppShell_Grid.o*`, `Menu.mif` | структура и иконки папок установлены; **pixel grid не измерена** |
| Folder layout и порядок | `appshelldata.xml` | вложенность и порядок **подтверждены**; прямоугольники ячеек/заголовка не измерены |
| App/folder icon render size | MIF-контейнеры и generic MBM 30×40 | **не установлено**; 30×40 generic fallback нельзя переносить на MIF-иконки |
| Selection/highlight rect и анимация | горизонтальные MBM strips; theme MIF/SKN | кандидаты найдены, **назначение и реальные размеры не установлены** |
| Scrollbar width, thumb, шаг | `avkon2.mbm` и Avkon MIF | **не установлено** |
| Текст: шрифт, кегль, baseline, line height | Nokia/S60 font-файлы и бинарные ресурсы | **не измерено**; вывод по имени TTF недостаточен |
| Active Standby: строки и плитки | `Idle`, `MscaAiPluginImages`, `ShortcutPlugin`, RSC | источники найдены, **геометрия не установлена** |

Ни один неустановленный параметр здесь не превращён в макетное число. Это также означает, что сейчас нельзя утверждать «сетку 3×4», «высоту status pane 30» или координаты softkey baseline только по извлечённым файлам.

## План измерения через EKA2L1

1. Импортировать этот RM-320 в EKA2L1 и зафиксировать версию/активную тему, язык и портретную ориентацию. Снять без масштабирования пиксельный кадр 240×320 Home, Main Menu, каждой папки, options menu, выделенного элемента и экрана со скроллом.
2. Измерить в самих кадрах границы status/main/control pane, прямоугольники ячеек, шаг сетки, icon render boxes, baselines, рамки выделения, scrollbar track/thumb и softkey labels. Для анимации снять несколько последовательных кадров с временем.
3. Сопоставить пиксельные паттерны кадров с конкретными MBM image ID и декодированными MIF. Если EKA2L1 отображает другое состояние темы, отметить это отдельно; не переносить размеры из неподходящего скина.
4. Проверить портретный и оба landscape-режима, поскольку `Wsini.ini` задаёт разные места softkeys. Результат пометить версией эмулятора и скриншотом-источником.

## Ограничения будущей Android-адаптации

После подтверждения S60-прямоугольников их можно хранить в координатах исходного режима и переносить на фактическую **область содержимого** Android с единым коэффициентом масштаба, например `s = min(W/240, H/320)` для портретного эталона. X и Y масштабируются одинаково; свободное пространство и расположение отдельных компонентов решаются отдельными правилами компоновки, а не растяжением картинки. В landscape исходный режим — 320×240, с отдельной проверкой расположения softkeys.

Для Samsung A5 нельзя считать весь аппаратный экран 1920×1080 доступным Launcher: нужны фактические `WindowInsets` системных и навигационных областей (совместимые с API 26), плотность дисплея и проверка вращения. Касательные области softkeys и иконок проектируются в `dp`, текст — в `sp`, а legacy-графика — с контролируемым единым масштабом. Подписи softkeys останутся визуально S60, но их hit areas должны быть удобны для пальца. Все главные действия доступны touch: tap, long press, scroll/swipe и Back. Виртуальный D-pad или имитация аппаратных клавиш не требуются.

Эти положения — требования к будущей архитектуре, **не** уже измеренная геометрия Nokia и **не** реализация Launcher.
